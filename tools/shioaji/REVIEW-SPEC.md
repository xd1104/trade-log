# 【回顧】分頁 — 設計規格（給 lab-dev）

> 對應可試用 demo：`tools/shioaji/review-demo.html`（雙擊即開，不需要伺服器）。
> **規格有疑義時以 demo 的實際手感為準**，這份文件是把 demo 講清楚，不是另一套設計。
> demo 的資料是寫死的假資料；正式版一律走 API。

## 0. 這一頁的目的（先讀，會影響每個取捨）

08:45~09:30 這個時段**已經被走查驗證證明沒有統計優勢**（AUC 0.46~0.49）。
所以【回顧】**不是拿來找訊號的**，是讓 Benson **練習與檢討自己的判斷**。

**紅線（不可違反）**
- UI 上不得出現任何**預測、勝率預估、期望值、買賣建議、訊號強度**，也不要出現「相似歷史情境的後續走勢」這類暗示。
- 只顯示**已經發生的客觀數字**（動能／跳空／震幅／位階／量能／他自己的紀錄）。
- 重播的計分只用**次數**（停利幾次、停損幾次、與當天同向幾次），**不要換算成勝率百分比**——那會被讀成「我這套有 X% 勝率」。
- 練習下單一律模擬，不送單。

## 1. 版面

### 1.1 分頁
- 頂列中間放 segmented 分頁：`即時` / `回顧`，沿用 `.seg` 的視覺（金色 on 態）。
- **切換不重載頁面、不重建 DOM**：兩個 `<div>` 用 `hidden` / `display:none` 互切。
- 切到【回顧】時，**後端的即時報價、持倉監控、±100 自動停利停損完全不受影響**（那些跑在 shioaji 回呼裡）。
- 前端 `tick()` 維持每 500ms 打 `/api/state`（成本極低），但**在 `TAB!=='live'` 時不要動即時分頁的 DOM**；切回來時立刻呼叫一次 `tick()`。
- 【回顧】的資料**不要**掛在 500ms 的 tick 上，只在「切進來 / 換天 / 換週期」時抓。

### 1.2 目標尺寸：1600 × 950 一頁看完，不捲整頁

| 區塊 | 尺寸 |
|---|---|
| `.app` | `max-width:1560px; padding:0 22px 24px` |
| `.cols` | `grid-template-columns: minmax(0,1fr) 400px; gap:16px` |
| 圖卡 `.card.chart` | `padding:14px 16px 12px` |
| SVG | `viewBox="0 0 1040 430"`、`preserveAspectRatio="none"`、`width:100%; height:auto` |
| 客觀盤面條 `.fstrip` | 7 欄等寬 grid，`gap:1px` 用 `--line` 當分隔線 |
| 交易列表 `.list` | `max-height:268px; overflow-y:auto` |

**左欄（上到下）**：圖卡（標題列／OHLCV 圖例／SVG／重播控制列） → 「進場當下的客觀盤面」7 格。
**右欄**：模式切換（翻紀錄／重播練習） → 該模式的操作區。

### 1.3 視覺
- **完全沿用 `live_panel.py` 既有的 CSS 變數**，不要新增顏色。台股慣例：`--up` 紅＝漲／賺、`--down` 綠＝跌／賠。

## 2. 模式 A：翻紀錄

### 2.1 交易列表 ←→ 圖表連動
- 列表沿用既有 `row()` 的排版（日期／方向徽章／進→出／結果點數），**新增**：整列可點、選中時 `.trade.sel`（金色框＋金色底），有寫理由時第二行顯示 `「…」`。
- 點任一筆 → 圖表切到**那一天**，並把畫面**縮放定位到那一筆**（不是顯示整天）：
  視窗寬度 `n = max(基本值, (出場index - 進場index) * 2 + 邊距)`，右緣落在出場後約 35% 視窗寬處。1 分 K 基本值 45 根、5 分 K 基本值 12 根。
- 選中的列要 `scrollIntoView({block:'nearest'})`。

### 2.2 圖上的標記
| 元素 | 畫法 |
|---|---|
| 進場 | 三角形（多＝向上紅、空＝向下綠）＋右側 `HH:MM 價格` |
| 出場 | ✕（賺紅、賠綠）＋右側 `HH:MM 價格　±點數` |
| 進出場之間 | 兩層矩形：① 進場價~出場價之間填色（賺紅、賠綠，opacity .16）；② 整條時間帶淡白底（opacity .025）標示「這段是持倉中」 |
| 停利／停損 | 進場價 ±100 的水平虛線（紅／綠）＋左側標籤 |
| 下單時段 | 08:45~09:30 金色底色 opacity .05（沿用既有做法） |
| 09:30 | 金色垂直虛線＋`09:30` 標籤（下單時段結束） |

- 價格軸要**容得下停利停損線**：選中交易在畫面內時，`hi=max(hi, entry+110)`、`lo=min(lo, entry-110)`。

### 2.3 鍵盤
| 鍵 | 行為 |
|---|---|
| `←` `↑` | 上一筆（清單往上） |
| `→` `↓` | 下一筆（清單往下） |
| `R` | 重播這一天（切到模式 B，蓋住結果） |

順序**依目前篩選後的清單**，不是全部紀錄。焦點在 `<input>` 時不吃鍵盤。

### 2.4 篩選
`全部 / 只看賺的 / 只看賠的 / 做多 / 做空`（單選 chips）。切換後若目前選中的那筆被濾掉，自動選清單第一筆。

### 2.5 「這一筆」明細卡
大字淨點數（紅／綠）＋方向＋出場原因＋台幣金額；下面依序：
進場（時間 價格）／出場／抱了多久／**進場後最順 +N 點**／**進場後最逆 -N 點**／當時寫的理由（沒寫顯示「（當時沒寫）」）／`重播這一天（蓋住結果）` 按鈕。

> 「最順／最逆」＝ MFE / MAE，**從進場的下一根算起**。進場那一分鐘的低點多半發生在進場之前，算進去會誤導。

## 3. 模式 B：Bar Replay（本頁最重要）

### 3.1 為什麼要這個
看已經走完的圖沒有練習價值，答案就在圖上。重播把後面的 K 棒蓋住，讓他在**不知道結果**的狀態下按 ▲／▼，之後才揭曉並跟他當天實際的決定對照。

### 3.2 狀態機

```
idle ──開始重播──> paused ⇄ running ──按▲/▼──> holding(自動續播)
  ^                   │                              │
  │                   └──「今天不做，直接揭曉」────┐  │碰到 ±100 / 11:00
  └── 再玩一次這天 ────── revealed <──────────────┴──┘
                             ^   沒判斷且走到 10:00 也自動進 revealed
```

| 狀態 | 右欄顯示 |
|---|---|
| `idle` | 日期選擇＋「怎麼玩」說明＋「開始重播」 |
| `paused` / `running` | **判斷卡**：▲做多／▼做空 大按鈕、`為什麼進？` 輸入框、「今天不做，直接揭曉」、鍵盤提示 |
| `holding` | **持倉卡**：浮動點數大字、進場資訊、停利／停損價、「直接看結果」 |
| `revealed` | **揭曉・對照卡**（見 3.5） |

### 3.3 播放控制列（放在圖的**正下方**，眼睛不用離開圖）
`⏮ 回到08:45` `◀ 退一根` `▶播放／❚❚暫停`（主按鈕、金色） `▶▶ 下一根` `×0.5 ×1 ×2 ×4` 右側顯示 `08:52　8 / 300 根`。
速度對應每根間隔：`×0.5=1200ms、×1=600ms、×2=300ms、×4=150ms`。

鍵盤：`空白鍵`播放/暫停、`→`下一根、`←`退一根、`↑`做多、`↓`做空、`Enter`揭曉。
（`↑↓→←` 都要 `preventDefault()`，否則整頁會跟著捲。）

### 3.4 遮住未來 —— 三個都要做到，少一個就洩漏答案
1. **K 棒**：只畫 `index <= rev` 的；右邊未揭曉區蓋 45° 斜線 pattern＋置中文字「後面還沒揭曉」。
2. **價格軸**：**只能用已揭曉的 K 棒算範圍，而且只擴不縮**（`hi=max(舊hi,新hi)`、`lo=min(舊lo,新lo)`）。
   ⚠️ 如果照整天的高低點定軸，光看「軸有多寬」就知道等一下會走多大 —— **這是最容易被忽略的洩漏**。
   反過來每根都重新貼合又會整張圖跳動，所以用「只擴不縮」。持倉時把 tp/sl 納入範圍（那不算未來資訊）。
3. **X 軸視窗**：`end = rev + 1 + 10`（右邊固定留 10 格空白），使用者只能改「看幾根」（滾輪 20~120），**不能平移到未來**。hover 十字線也要 clamp 在 `rev` 以內。

### 3.5 揭曉 → 對照
觸發：碰到 ±100／11:00 仍未觸及（收盤價結算）／沒判斷走到 10:00／按「直接看結果」。

揭曉時：
- 整天全部揭開（`rev = 最後一根`），但**畫面停在「判斷的那一段＋後續 40 分鐘」**，不要跳到下午去。視窗左緣拉回 08:45。
- 圖上同時畫**你這次的進出場**（實心標記）與**當天實際的進場**（金色虛線圓圈＋「當天你的進場」）。
- 右欄兩張並排卡：

```
你這次的判斷      ▲多  09:02  45380 → 45480      +95
                 「你寫的理由」
當天你實際的決定   ▲多  09:02  45401 → 45501      +95
──────────────────────────────────────────
        方向一致　時間也一樣          ← 判定條（一致＝金色，不一致＝灰）
   重播 1 次 ｜ 停利 1 ｜ 停損 0 ｜ 與當天同向 1
```

判定條文案（只描述事實，不評價對錯）：
- 都有進場 → `方向一致 / 方向相反` ＋ `時間也一樣 / 你早了 N 分鐘 / 你晚了 N 分鐘`
- 只有你進 → `當天你沒進場，這次你進了`
- 只有當天進 → `當天你有進場，這次你選擇觀望`
- 都沒進 → `兩次都沒進場`

按鈕：`再玩一次這天`（重置到 idle）／`換下一天`。
`revealed` 之後 `→` `←` 逐根失效（要重玩請按按鈕），避免遮罩又跑出來。

### 3.6 判斷的規則（跟正式練習下單一致）
- 進場價 = 按下當根的**收盤價**；`tp = 進場 ±100`、`sl = 進場 ∓100`。
- 逐根檢查 `h/l` 是否觸及；**同一根同時觸及 tp 與 sl 時算停損**（保守，且要在程式碼註解寫明這個約定）。
- 結果點數扣 `FEE_POINTS`（5 點）再顯示，數字才跟他的練習紀錄同一把尺。

### 3.7 重播週期
重播用 **1 分 K**。08:45~09:30 只有 9 根 5 分 K，逐根重播沒有練習密度。翻紀錄可切 `1 分 / 5 分`，預設 5 分。

## 4. 進場當下的客觀盤面（7 格）

`最近 5 分｜最近 15 分｜對開盤｜跳空｜今日震幅｜位階｜量能`
—— 欄位與即時面板 `chips` **完全一致**，這樣重播才是真的在演練那個畫面。

- 翻紀錄：顯示**該筆進場當下**的數值，標題寫 `進場當下的客觀盤面（08-12 09:02）`。
- 重播未判斷：顯示**目前這一刻**，標題寫 `目前這一刻的客觀盤面（09:02）`，隨播放更新。
- 重播已判斷：**凍結在按下去的那一刻**（那才是要檢討的盤面），不要跟著繼續跑。

計算沿用 `Today.features()` 的定義（`mom5/mom15/ret_open/gap/rng/pos/vol_ratio`），但要用**歷史 1 分 K 重算**，不能用即時物件。

## 5. 需要的 API

### 5.1 改：`GET /api/bars?date=YYYY-MM-DD&tf=1|5`
現況 `day_bars()` 固定用 `CHART_TF=5`。加一個 `tf` 參數（只接受 1 或 5，其他值回 400）。
`tf=1` 直接用 1 分 K，但**仍要走 `to_timeframe()` 的時間平移邏輯**（見第 7 點的坑）。
回傳沿用現況：`{date, bars:[{t,o,h,l,c,v}], trades:[…], traded:[…], others:[…]}`。

### 5.2 新增：`GET /api/review`
一次給回顧要用的全部紀錄，避免前端逐日抓。

```json
{
  "trades": [
    {"date":"2026-08-12","dir":"long","entry":45401,"exit":45501,
     "time":"09:02","_exit_time":"09:05","_reason":"tp","_net":95.0,
     "note":"","_source":"panel",
     "_mfe":100,"_mae":-21,
     "_snap":{"mom5":80,"mom15":48,"ret_open":30,"gap":70,
              "rng":125,"pos":0.76,"vol_ratio":0.81}}
  ],
  "days": ["2026-08-13","2026-08-12","..."]
}
```

- `_snap` / `_mfe` / `_mae` 由後端用該日 1 分 K 算好（前端不重算）。
- **算過就快取**（記憶體 dict + 落地一份 `practice_trades/_review_cache.json`，key 用 `date|time`）。歷史資料不會變，面板重啟後可重算但沒必要每次算。
- 該日沒有本機 K 棒時，`_snap`/`_mfe`/`_mae` 給 `null`，前端顯示「—」。

### 5.3 重播要不要落地？
**若要保留重播練習紀錄：必須寫到獨立檔案**（例如 `replay_log/YYYY-MM-DD.json`），
**絕對不可以寫進 `practice_trades/`** —— 那會混進他的真實練習勝率統計，把成績污染掉。
（第一版建議：重播計數只放記憶體、關掉就歸零，UI 上寫明「本次」。要不要留是待老闆拍板項，見第 8 節。）

## 7. 這個專案踩過的坑（照做，別再踩一次）

1. **圖表容器只建一次，之後只換 `<svg>` 的內容**（`sv.innerHTML = g`＋`setAttribute('viewBox', …)`）。整塊 `innerHTML` 重繪會打斷使用者正在進行的縮放／拖曳並且閃爍。右欄同理：先比對字串、真的變了才寫 DOM。
2. **永豐的 1 分 K 用「結束時間」標記**（日盤 08:45 開盤，第一根標 08:46）。`to_timeframe()` 已經把時間往回挪一分鐘處理好了 —— 新增 `tf=1` 時**要走同一條路**，不要另外寫一段直接吃原始 ts。
3. **重播時右欄每走一根就重繪 → 使用者打到一半的「為什麼進」會被洗掉**。重繪前先把 `input.value` 收進狀態變數，重繪後再放回去並還原游標位置（demo 有實作）。
4. **只存在記憶體的狀態要能從檔案還原**（面板會自動重啟）。回顧頁的資料本來就從檔案來，沒問題；但若之後要存重播紀錄，記得落地（且照 5.3 分開存）。
5. **價格軸洩漏答案**：見 3.4，這是這頁最容易做錯的一件事。
