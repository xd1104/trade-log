## 0. 這一頁的目的（先讀，會影響每個取捨）

即時分頁回答「今天走到哪」，【細節】回答「那 45 分鐘每一秒發生什麼」，回顧回答「我做得怎樣」。

這一頁回答**一個問題，而且只有這一個**：

> **「判斷方向」到底有沒有加分？**

作法是每個交易日 09:03:30 讓四種算法各記一筆**模擬**進出場，唯一的差別是方向怎麼決定，
其他（時刻、口數、±100、出場規則）全部一樣，然後把成績並排。

### ⛔⛔ 鐵律 1：永遠只是模擬，一張單都不會送出去

**這不是自動下單功能，也不是自動下單的前置作業。**
這一頁**不會、也不准**碰任何下單路徑：

- ⛔ 這一頁的程式碼**一行都不准** import `broker`、呼叫 `broker.*`、
  打 `/api/enter`、`/api/real/*`、或任何會產生委託單的東西。
- ⛔ 不准寫進 `practice_trades/`、`real_trades/`、`sim_orders/`、`real_orders/`。
  它有自己的資料夾（§3.3）。
- ⛔ 不准出現「要不要真的下單」的按鈕、開關、提示、或「將來可以…」的文案。
- 守衛：`autotest-backend.py` ⑫ 用 AST 掃描（負控組：同一把尺在 `hold_to_fire` 那段抓得到
  `broker` ⇒ 證明尺是活的）。

> 要不要真的下單是**以後另外的決定，而且要有實績才談**。
> 在那個決定發生之前，這一頁的存在本身不構成任何理由。
> **不要自作主張往那個方向鋪路。**

### ⛔⛔ 鐵律 2：這一頁天生離「紅線」很近，所以規則要比別頁更硬

CLAUDE.md 開宗明義：**UI 上不得出現任何預測、勝率預估、期望值、買賣建議、訊號強度。**
原本的「趨勢指數 0~100」就是因為這條被移除的 ——
理由寫著「**一個看起來可信卻無效的數字，比明顯沒用的更危險**」。

而這一頁**天生就在展示「程式判斷的方向」與「勝率」**。所以：

| 這一頁做什麼 | 這一頁絕對不做什麼 |
|---|---|
| 顯示「今天 09:03:30 程式**判斷**的方向是多」 | ⛔ 「今天**建議**做多」 |
| 顯示已經發生的模擬成績 | ⛔ 對明天的任何陳述 |
| 顯示四個方向，各自獨立 | ⛔ 「四個裡有三個做多」這種**綜合／多數決／共識**（那就是訊號強度） |
| 時刻過了才顯示方向 | ⛔ 09:03:30 之前**預告**「等一下會判斷做多」 |
| 樣本夠才給勝率 % | ⛔ 3 筆 2 勝顯示「67%」 |
| 天花板常駐在畫面上 | ⛔ 把天花板收進說明、tooltip、或摺疊區 |
| 顏色只給損益 | ⛔ 用紅綠標方向、筆數、門檻、訊號值 |

**這五個裝置是這一頁的骨架，不是裝飾（§4）。少任何一個，這一頁就不該上線。**

## 2. 四種做法

> ⚠️ 用字：對 Benson 講一律叫「**做法**」，不叫「算法／策略／模型」（他自己的用詞是「哪個做法」）。

### 2.0 ⛔⛔ 名字（v3 新增，這一節優先於本文件其他所有措辭）

**畫面上不准出現 A／B／C／D。** 代號只活在資料層。

| 資料層 key（⛔ 不變） | 畫面上的名字（⛔ 唯一寫法） | 成績表名字底下那行小字 |
|---|---|---|
| `A` | **5 分 K** | `09:00 起算` |
| `B` | **開盤起** | `08:45 起算` |
| `C` | **開盤起・要 {thr} 點** | `08:45 起算・不夠就不做` |
| `D` | **不判斷** | `一律做多（基準）` |

- **名字是 Benson 定的**，⛔ 不要自己改字、不要加「法」「策略」「模式」等後綴。
- `C` 的名字**帶著門檻值**（`開盤起・要 30 點`），值取自常數 **`C_THRESH`**。
  ⇒ 一定要寫成一個函式，⛔ 不准散在各處硬寫字串（否則改一次門檻要改七個地方）：

```js
// ⚠️ 面板的命名慣例是 at- 前綴；demo 裡叫 nm()/ORDER，正式版請用下面這組名字。
const AT_NAME  = {A:'5 分 K', B:'開盤起', C:'', D:'不判斷'};
const AT_ORDER = ['A','B','C','D'];   // ⛔ 所有區塊一律照這個順序
function atName(k){ return k==='C' ? `開盤起・要 ${C_THRESH} 點` : AT_NAME[k]; }
```

- **必須用 `atName()` 的地方（一個都不能漏，v2 這些地方全是代號）**：
  ① 今天卡的抬頭　② 成績表第一欄　③ 泳道左邊　④ 累計圖每條線尾端的標籤
  ⑤ 配對卡標題與內文（`5 分 K vs 不判斷`）　⑥ 天花板那行「目前『X』超過這條線」
  ⑦「這一天」頁尾的訊號值（`訊號 5 分 K −3 點 · 開盤起 +2.3 點`）
  ⑧ demo 控制台「假裝『開盤起』有效」。
- **順序一律 `AT_ORDER`**（5 分 K → 開盤起 → 開盤起・要 N 點 → 不判斷），
  今天的卡、成績表、泳道、累計圖標籤**四處必須同序**。⛔ 不准某一區自己排別的順序
  （例如「把不判斷排到最前面因為它是基準」）。
- ⚠️⚠️ **進階區的門檻滑桿（§10）⛔ 不准改動任何地方的名字。**
  它是「用同一批資料試算另一個門檻」，**真正在跑的還是 `C_THRESH`**（§10 已有這條規則）。
  ⇒ 正式版：滑桿只影響 `.at-adv` 那張掃描表，`atName('C')` 永遠讀 `C_THRESH`。
  ⚠️ **demo 是刻意做成不一樣的**（拉滑桿全站名字跟著變）—— 那是為了讓 Benson 一眼看見
  「名字自己會帶著規則」對任何門檻值都成立。**dev ⛔ 不要照抄 demo 這個行為。**
- ⛔ **不准為了塞得下而縮寫**（「開盤・30」「開30」都不行）。放不下就改版面，見 §9.3。
- ⛔ **不准在畫面任何地方留「A＝5 分 K」這種對照說明**。要是需要那行字，就代表命名失敗了。

### 2.1 定義

每個交易日 **09:03:30**，四種算法**同時各記一筆**。
⚠️ 09:03:30 是 2026-09-07 由 04:30 改過來的（他自己的決定），**寫成常數 `SIGNAL_AT`，不要散在程式各處**。

| key（⛔ 不上畫面） | 名字 ｜ 怎麼決定方向 | 訊號值 |
|---|---|---|
| `A` | **5 分 K** ｜ 09:00 那根 5 分 K 到現在是漲是跌（他原本的規則） | `P(09:03:30) − P(09:00)` |
| `B` | **開盤起** ｜ 08:45 開盤到現在是漲是跌 | `P(09:03:30) − Open(08:45)` |
| `C` | **開盤起・要 30 點** ｜ 同 B，但漲跌**超過 30 點才做**，不夠就當天不下單 | 同 B（另存門檻 `C_THRESH=30`） |
| `D` | **不判斷** ｜ 一律做多，完全不判斷（基準） | 無（固定 `+1`） |

**⛔ 四種唯一的差別只有方向怎麼決定。** 進場時刻、進場價、口數、±100、出場規則**全部一樣** ——
這樣比較才有意義。任何一個「順便也調整一下」的念頭都會毀掉這個實驗。

- 進場價：四條**共用同一個**「09:03:30 的成交價」。
  ⇒ 四條的 ±100 位置**完全相同**，圖上兩條線畫一次就好（§9.3）。
- ⛔ 訊號值 `== 0` 時算做多（跟 D 同向）。要寫死並在測試裡釘住，不要讓它變成第三種狀態。

### 2.2 為什麼一定要有 D（⛔ 這一段不可以刪，以後一定會有人覺得它多餘）

CLAUDE.md 記著 2026-08-11 用 506 個交易日做的完整驗證：

| 測的東西 | 結果 |
|---|---|
| 首根 5 分 K 順勢做 ±100 | 勝率 50.8%、每筆 −4.6 點 |
| 趨勢指數（kNN 相似情境） | AUC 0.46~0.49，等於丟銅板 |
| 邏輯迴歸 / 梯度提升樹 | AUC < 0.5，**不是方法太弱，是資料裡沒有這個資訊** |
| **每天固定做多（完全不看模型）** | **每筆 +1.78 點 —— 比所有模型版本都好** |

**所有會判斷方向的模型，全部輸給「每天固定做多、什麼都不看」。**

⇒ **「不判斷」不是陪跑的，它是目前的冠軍。**
沒有對照組的話，「5 分 K」跑出 +150 點看起來很棒，但如果同期間「不判斷」是 +400 點，
那個 +150 的真正意思是「判斷讓我少賺 250 點」。

⛔ 所以「不判斷」在畫面上**不可以**被畫成次要的（不准縮小、不准放最後一列還加註「僅供參考」）。
demo 裡它在累計圖上是**最粗的那條白線**，成績表的小字寫「一律做多（基準）」，
配對區的標題寫「跟『不判斷』比」。
⚠️ v3 之後**沒有圖例了** ⇒ 「基準」這個身分靠**線最粗＋成績表小字＋配對區標題**三處承擔。

### 2.3 ⛔⛔ 09:03:30 這個時刻沒有被證明比較好，而且回測切不出它

## 3. 每天記什麼（資料契約 —— 這一節決定二十天後你還能不能改主意）

### 3.1 ⛔ 記數值，不只記方向

「跌 156 點」不是只記「跌」。
理由：**二十天後想試「要跌超過 50 點才做」，用同一批資料就算得出來，不用再等二十天。**

同理，**能記的中間值全部都記**。磁碟成本是每天一列 JSON（幾百 bytes/年），
而漏記一個欄位的代價是「再等二十天」。

### 3.2 一天一列的欄位

```jsonc
{
  "date": "2026-09-08",
  "src": "live",              // live＝當天即時報價／backfill＝從 tmf_1min.csv 回填（§2.3！）
  "at": "09:03:30",           // 實際記錄的時刻（不是設定值 —— 有可能晚了幾百毫秒）
  "at_lag_ms": 180,           // 距離 09:03:30.000 差幾毫秒。⛔ 不可以不記，這是資料品質
  "px": 12158.4,              // 09:03:30 的成交價（四條共用的進場價）
  "bid": 12158.0, "ask": 12159.0,   // 進場當下的買賣價（滑價與價差事後才算得出來）
  "ref": {                    // 訊號的原料，⛔ 全部要記，不要只記算完的結果
    "open0845": 12140.2,      // 08:45 開盤
    "p0900":    12160.7,      // 09:00
    "prev_close": 12102.0,    // 上一個交易日日盤收盤（跳空基準）
    "hi0845_0903": 12171.5, "lo0845_0903": 12133.0,   // 進場前的高低（當天波動度基準）
    "rng20": 78.4             // 近 20 個交易日的日盤平均振幅（波動度基準線）
  },
  "sig": { "A": -2.3, "B": 18.2 },  // ⛔ 數值，不是 "up"/"down"
  "runs": {
    "A": {"dir": 1,  "exit_at":"13:40:12", "exit_px":12258.4, "pts": 100.0, "why":"tp",  "both": false},
    "B": {"dir": 1,  "exit_at":"13:40:12", "exit_px":12258.4, "pts": 100.0, "why":"tp",  "both": false},
    "C": {"dir": 0,  "skip": "below_threshold", "thresh": 30},
    "D": {"dir": 1,  "exit_at":"13:40:12", "exit_px":12258.4, "pts": 100.0, "why":"tp",  "both": false}
  },
  "quote_gaps": 0             // 記錄期間報價中斷幾秒（⛔ 不可以安靜地少）
}
```

- `why` ∈ `tp`（+100 觸價）／`sl`（−100 觸價）／`eod`（都沒摸到，收盤平）。
- `both`：**同一根 K 棒/同一秒同時摸到 ±100**（分不出誰先到）⇒ **保守算停損**，
  並且 `both:true`。⛔ 這個筆數要在畫面上顯示（§6.3），
  不然回測最經典的陷阱（把雙觸日算成停利）會在你眼皮底下發生。
  ⚠️ 用即時報價逐筆判斷時 `both` 幾乎不會發生；**用 1 分 K 回填時很常發生**（§2.3）。
- `skip`：C 沒做的日子**要有一列**（`dir:0` ＋ 原因 ＋ 當時的門檻），
  ⛔ **不可以整天不寫** —— 「那天沒做」跟「那天沒錄到」必須分得出來。
- ⛔⛔ **結算窗口：從標籤 `09:04` 那根（含）開始，比較一定是 `>=`**
  （2026-09-07 lab-qa 退件 R2，實作補上）。`one_min_bars()` 走 `to_timeframe()`
  ⇒ **標籤是「起始時間」**：標籤 `09:03` 那根涵蓋 09:03~09:04（含 09:03:30 進場前的價，
  要排掉）、標籤 `09:04` 那根涵蓋 09:04~09:05（**整根都在進場之後，本來就該收進去**）。
  舊實作寫成 `>` ⇒ 實際用到的第一根是 **09:05**、盲區變成 **90 秒**，
  而畫面副標還寫著「出場從 09:04 開始算」＝**一句假話**。
  盲區的正確說法是 **09:03:30~09:04:00 這 30 秒**。
  守衛：`autotest-backend.py` ⑤b（斷言「settle 用到的第一根標籤 == 09:04」
  ＋「寫進 `settle_from` 的值跟真的用到的第一根一致」，負控組就是改回 `>`）。

### 3.3 檔案

```
tools/shioaji/autotest/YYYY-MM.jsonl      一個月一個檔，一天一列
```

- ⛔ **一定要 gitignore**（跟 `practice_trades/`、`real_trades/` 同一個處置）。
  雖然裡面沒有他真的下單，但它含**進場價與時間**，而且 repo 是公開的。
- ⛔ **不可以跟 `practice_trades/` 或 `real_trades/` 共用資料夾或檔名**。
  面板已經為「練習與重播混用會污染勝率」立過同一條規矩。
- ⛔ **`src:"backfill"` 與 `src:"live"` 存在同一個檔沒關係，但統計時一定要分開**（§6.4）。
- 一定是 `open("a")`。看門狗重啟是常態，覆寫＝弄丟當天的資料（`TODAY_TRADES` 已經這樣弄丟過真資料）。
- **同一天重複寫入要擋**：以 `date` 為鍵，已經有 `src:"live"` 的那天就不再寫。
  看門狗在 09:03:30 前後重啟時會重跑一次判斷。

### 3.4 09:03:30 那一刻怎麼記（⛔ 不准碰 `on_tick`）

- 主迴圈（4Hz）自己判斷「跨過 09:03:30 了沒」，跨過就從 `STATE` 讀當下的價，**記憶體裡先組好那一列**，
  丟給一個獨立的寫檔執行緒落地（跟 `tick_writer.py` 同一招）。
- ⛔ **`on_tick` 一行都不准加。** 那條回呼執行緒更新的價**就是他的停損**
  （永豐沒有停損單，停損活在 Python 迴圈裡）。
- ⛔ 出場判斷**不是**開一個新的監控迴圈。四條的 ±100 是**事後從 K 棒／逐筆算出來的**，
  不需要即時。做法：當天 13:45 之後（或下次開面板時）補算 `runs`，
  沒補算完的那幾天在畫面上標「結算中」。
  **理由：多一條即時監控迴圈＝多一個會跟停損搶 GIL 的東西**（CLAUDE.md「不碰 state_lock ≠ 零成本」）。
- 09:03:30 那一刻**收不到報價**（斷線／休市／國定假日）⇒ 那天**整天不寫**，
  並在畫面上列進「沒有記錄的日子」。⛔ **不可以拿舊價頂替** ——
  面板已經有一條「沒有即時報價一律不准開模擬單，這是紀錄正確性不是 UX 取捨」。

## 4. 紅線的裝置（⛔ 這一節是這一頁的骨架）

### 4.0 ⭐ 裝置零：進度尺 —— 這一頁唯一要傳達的那句話，用畫的

**要傳達的是**：「這個測試要跑大概兩年才有答案，不是二十天。」
**但畫面上不准寫這句話**（也不准寫「統計檢定力／MDE／顯著」任何一個詞），
改成同一條軸上的兩個點，讓他自己看出來：

```
這個測試跑到哪裡了                                   20 / 505 筆
[▮▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯▯]
現在                                          要到這裡才算數
20 天                                              約 2 年
```

- 位置：**分頁最上面**（`.at-track`），在「今天」卡之前。
- 進度 = `已累積筆數 / 505`；填色 `--gold`，`width:max(1.1%, n/505*100%)`（1 筆也要看得見）。
- 右上大字 `n / 505 筆` 用 `--font-mono` + `tabular-nums`，**不加百分比**。
- 「約 2 年」＝ 505 個交易日 ÷ 約 245 天/年。⚠️ **這個 505 跟 §7.1 是同一個數**，
  §7.1 的常數改了這裡要跟著改（做成同一個常數，別各寫各的）。
- `title` 放一句話的注腳：「505 筆 ≈ 兩年。那是『每筆差 12 點也分得出來』所需的天數；
  在那之前，排名會一直換人。」
- ⛔ 不准把它做成「還剩 485 天就會有答案」的倒數 —— 那是承諾，不是事實
  （跑滿了也可能結論是「都沒差」）。
- ⚠️ 它必須跟著「累積天數」即時變 —— demo 的價值就在他按下 `120` 之後看到棒子只走了四分之一。

### 4.1 裝置一：「模擬 · 不送單」鎖印

- **一顆就好**（v1 是橫幅＋兩顆藥丸，被退件）：掛在**「今天」卡的標題旁**
  `⚪ 模擬 · 不送單`，那是第一屏、最容易被截圖、最容易被誤讀成「面板在自動交易」的地方。
- 「這一天」卡不再掛藥丸 —— 那張圖上本來就畫著 `09:03:30 模擬進場 12158.4`，**圖自己有講**。
- ⛔ 不准全部拿掉：`.simlock` 在畫面上**必須恰好有 1 顆**，且**不可關閉**（驗收要真的數，§15）。
- **顏色用 `--gold`**。理由：金色在這個面板的既有意思是
  「即時／現在／選取／**這是什麼種類的資料，注意**」——
  【細節】分頁的「取樣」金籤就是最後那個用途，這裡沿用**不是新增意思**。
  ⛔ 不可以用紅綠（紅綠只給損益，見 §4.4）。
- 探針要**真的量畫面上有幾顆**（`.simlock` **恰好 1 顆**且可見），不是掃原始碼。

### 4.2 裝置二：時態鎖 —— 時刻過了才顯示，⛔ 不預告

| 現在 | 「今天」卡顯示什麼 |
|---|---|
| < 09:03:30 | 「今天 09:03:30 還沒到」＋**一句**「時刻到了才會記下方向。」（⛔ 不預告的**理由**放 `title`，不要印在畫面上） |
| ≥ 09:03:30 | 四個方向（已經發生的事實）＋ §4.3 那句話 |
| 非交易日／沒錄到 | 「今天沒有記錄」＋原因 |

⛔ **不可以**在 09:03:30 之前顯示「目前 A 會判斷做多」「還有 2 分 30 秒」這類東西。
那是預測，而且是最像「建議」的一種形狀。
⚠️ 判斷「時刻到了沒」一律用**後端的 `snapshot()["today"]` 與後端時鐘**，
⛔ 不可以用瀏覽器的 `new Date()`（跨午夜兩邊會不同一天，面板已經為這件事踩過一次）。

### 4.3 裝置三：⛔ 沒有綜合（v2：規則留著，那段字收起來）

**v1 在四格底下貼了一段「這不是建議／沒有綜合」的常駐文字 —— v2 刪掉，改放 `.at-about`。**
理由：那段字是講給「怕他誤會」的我們自己聽的，他看到的只是一牆字；
而**真正的防線是「畫面上沒有東西可以看」**，不是那段字。

- ⛔ **不准**有任何跨算法的聚合：多數決、共識、幾比幾、平均方向、加權方向、「一致性」。
- ⛔ **不准**把四格排出優劣順序、不准把「目前成績最好的那個」標起來。
  （成績表裡它們自然有順序，那是**已發生的統計**；今天那四格是**同一件事的四種算法**，不分高下。）
- 每一格顯示：**名字**（`atName()`，⛔ 不是字母 —— §2.0 優先）＋ 起算點那行小字 ＋ 方向
  ＋ **訊號值** ＋（結算完之後）出場結果。
- 「開盤起・要 N 點」沒做的日子顯示「這天不做」＋ 訊號值，
  ⛔ 不可以整格消失（消失＝壞掉）；⛔ 也不要再重複寫門檻（名字裡已經有了）。

### 4.4 裝置四：顏色只給損益（⛔ 比別頁嚴格）

| 東西 | 顏色 |
|---|---|
| 點數、賺賠、K 棒漲跌、泳道 | `--up` 紅／`--down` 綠（台股慣例） |
| **方向（做多／做空／不做）** | ⛔ **中性 `--text` / `--faint`，不准紅綠** |
| 訊號值、筆數、勝率 %、門檻、天花板、天數 | `--dim` / `--faint`，⛔ 不准紅綠 |
| 「模擬·不送單」、「只有 N 筆」、注意類 | `--gold` |
| 證不出來帶 | `rgba(141,149,163,.075)` ＋ 虛線邊 |

⚠️ 即時分頁的 `.n-row .d.l{color:var(--up)}` 對「做多」用紅色 —— **那是既有語言，不要去改它**。
但**這一頁的「今天判斷的方向」刻意不沿用**：那一格是全站唯一一個「程式現在說了什麼方向」的地方，
染成紅色會讓它看起來像一個令人興奮的訊號。這是**取捨，不是疏忽**，請 PM 確認（§16-1）。

### 4.5 裝置五：天花板一行（常駐）＋〈這一頁在算什麼〉（摺疊）

**天花板**（`.at-ceil`）還是貼在成績表正下方、還是常駐，但 v1 的三行砍成**一行**：

```
● 20 筆 ⇒ 只分得出「每筆差 60.8 點以上」。目前沒有一條超過
```

- 第二段（`目前沒有一條超過` / `目前 A、B 超過這條線（一次超過不等於證明）`）用 `--gold`。
- 「比這個小的差距跟運氣分不開」「505 筆時是 12.1 點」→ 進 `title`。
- 「要 505 筆／約兩年」這件事**由 §4.0 的進度尺負責**，這裡不再重複
  （同一件事講三次，只留最短那次）。

**〈這一頁在算什麼〉**（`.at-about`，`<details>`，⛔ **預設 `open=false`**）：
v1 平鋪在畫面上的字全部住這裡，一句一條、不成段：

2. 永遠只是模擬，一張單都不會送出去

4. 沒有「四個裡三個做多」這種綜合（§4.3）
5. 不到 30 筆不給勝率 %（§6.2）
6. **D 目前是冠軍**：506 天的驗證裡會判斷方向的模型全部輸給固定做多（§2.2）
7. 09:03:30 沒有被證明比 09:04:30 好（§2.3-1）
8. 回測成績與上線後的成績不可以加在一起算（§2.3-2）
9. 為什麼是 505 筆／約兩年（§4.0、§7.1）
10. 資料來源（即時報價記一筆；他自己那一欄讀 `real_trades/`）

⛔ **不准**把它預設打開，也**不准**把裡面任何一條搬回平鋪畫面 ——
這些條目在 v1 就是平鋪的，退件原因就是它們。

### 6.1 欄位

- 第一欄第一行是 `nm(k)`（`--text`、600、12.5px），第二行是 §2.0 那句小字（`--faint`、10.5px）。
  ⛔ 表頭寫「**做法**」不寫「算法」（他自己的用詞）。
- ⚠️ 名字比代號寬 ⇒ `.tbl{min-width:700px}`（v2 是 640）。
  ⛔ **不可以改成壓縮欄寬**，窄的時候整張橫向捲（§1.3 已有的決定）。

- 主角是**累計點數**（大字、紅綠），**勝率是中性色小字**。
  ⚠️ 這是沿用面板既有的設計決定，不是我的偏好 ——
  `live_panel.py` 的 `.score` 註解寫著：「舊版全頁最大最亮的數字是金色的勝率……
  把勝率捧到視覺頂端也等於暗示這個工具在追勝率。現在：勝率降成中性色，

  否則 `在雜訊裡 (<X 點)`（中性籤）。

### 6.2 ⛔ 樣本少的時候不給百分比（這是這一頁最重要的一條）

## 7. 「證得出來嗎」怎麼算與怎麼畫

### 7.1 天花板的算式

錨點：**PM 用 `tmf_1min.csv` 503~507 天回測，算出這批資料只測得出「每筆 > 12.1 點」的優勢。**

```
天花板(n) = 12.1 × sqrt(505 / n)          # 每筆，點
累計的 95% 帶 = ±(12.1 × sqrt(505)) × sqrt(n) = ±271.9 × sqrt(n)   # 點
```

推算值（**⛔ 這一欄是 lab-ux 用 √n 縮放推的，不是量出來的**）：

| n | 10 | 20 | 60 | 120 | 250 | 505 |
|---|---|---|---|---|---|---|
| 每筆門檻（點） | 86.0 | 60.8 | 35.1 | 24.8 | 17.2 | **12.1** |

#### 「8 點」與「12.1 點」不矛盾 —— 它們回答兩個不同的問題（PM 2026-09-07 更正）

| 數字 | 出處 | 它回答的問題 | 算式 |
|---|---|---|---|
| **約 8 點** | CLAUDE.md（σ=89.7、506 天） | 「差多少**才算顯著**？」＝ 只要求「不是雜訊」 | `1.96 × σ / √n` ⇒ `1.96 × 89.7 / √506 ≈ 7.8` |
| **12.1 點** | PM 用 `tmf_1min.csv` 503~507 天 | 「差多少**才有八成機率被抓到**？」＝ 還要求「測得到」 | `(1.96 + 0.84) × σ / √n` ⇒ `2.80 × 96.8 / √505 ≈ 12.1` |

- 兩者比值 `2.80 / 1.96 = 1.43`，**差的那 43% 就是「被抓到的機率從五成提到八成」的代價**。
- **σ 也不同（89.7 vs 96.8）**：那是**出場規則不同**造成的 —— CLAUDE.md 那組是舊的出場口徑，
  這一頁是 **±100 停利停損**（截斷了尾部、但也改變了分佈），所以單筆報酬的標準差不一樣。
  ⛔ 不要把兩個 σ 混用在同一條算式裡。
- **這一頁一律用 12.1 那一條**（要的是「跑多久才會知道」，不是「事後能不能宣稱顯著」）。
- ⚠️ 但 **UI 上只能出現一個數字**：畫面只講「現在 n 筆 ⇒ 只分得出每筆差 X 點以上」＋進度尺，
  ⛔ 不准把 8 與 12.1 兩個都印出來，那只會讓人覺得我們自己也算不清楚。

⛔⛔ **dev 仍然不可以照抄上面那一列當成量過的數字。**
CLAUDE.md 明訂「這個專案的設計備忘裡不可以放沒量過的數字 —— 下一個人會照著它做決定」。
上線前要做兩件事：

1. **跟 PM 要 σ=96.8 的出處**（哪一段資料、什麼出場規則、有沒有扣費），
   把 `σ`、`2.80`、`505` 三個常數與算式一起寫進程式註解，並在 UI 的 `title` 標出處。
2. **自己重算一次**並在 `test_autotest.py` 釘住幾個定點值（至少 n=20 與 n=505）。
   ⚠️ 上表那一列（86.0 / 60.8 / 35.1 / 24.8 / 17.2）是 lab-ux 用 √n 縮放推的，**不是量出來的**。

⚠️ **20 筆的門檻是 60.8 點，而 ±100 停利停損的上限就是 100 點/筆** ⇒
**二十天基本上什麼都證不出來。**
⛔ 這句話**不准寫在畫面上**（v1 寫了，Benson 的回應是「聽不懂」）——
要讓他**自己看到**：進度尺停在 `20 / 505`（§4.0）、成績表每一列都掛「在雜訊裡」，
按下控制台的 `120` 之後棒子也只走了四分之一。**這是本頁的第一設計目標。**

### 7.2 累計點數圖 ＋ 證不出來帶

- x = 第幾筆，y = 累計點數。四條 ＋ 他自己一條。
- **證不出來帶**：一條隨 `√n` 張開的灰色喇叭（`±271.9√n`），填色 ＋ 虛線邊。
  **任何一條線只要還在帶子裡面，就代表「這份資料證不出它跟 0 有差別」。**
  ⇒ 把統計功效變成**視覺物件**，他不用讀數字，看線有沒有跑出帶子就知道。
- ⛔ **顏色不編碼好壞**（紅綠只給損益數字）。五條靠亮度與線型分：
  `不判斷` = `--text` 粗實線（基準）／`5 分 K` = `--text` 細實線／`開盤起` = `--dim` 實線／
  `開盤起・要 N 點` = `--dim` 虛線／`你自己` = `--gold` 粗實線。
- ⛔⛔ **v3：圖例整個刪掉**。圖例就是「線型 → 是誰」的對照表，正是這一輪要根除的病。
  **名字直接寫在每條線的尾端**（`600 11px` sans、線本身的顏色）：
  - 右邊留白 `RM = ceil(max(measureText(每個名字))) + 16`（實測 101px），**量出來的不准寫死**；
  - **刻度數字整排搬到左邊**（右對齊 `LM-8`，`LM=42`），右邊整條讓給名字；
  - 名字上下擠在一起時**往下推開**（最小間距 14px），推開的那個補一條 45% 透明的細引線
    接回線尾。⛔ 不准改成縮字、省略、或退回代號。
  - 整批超出下緣就整批上移（demo 有實作，n=120 五條全擠時實測不重疊）。
- **n < 10 不畫線**，改空狀態：`只有 N 筆，還不畫線` ＋ `滿 10 筆才開始畫`（兩行短句）。
  「三、四個點連起來看起來就像一條趨勢，但那只是三、四個點」進 `title`。
- 價格軸沿用 `niceStep()`（1/2/2.5/5/10×10ⁿ）。⚠️ 這張圖資料只增不減、x 軸範圍每天變 ⇒
  **遲滯結構上不承重**（跟【細節】同一個坑，見 TICK-TAB-SPEC §4.1 的更正），**不要抄遲滯那一段**。

## 8. 跟「不判斷」的配對對照（⛔ 這一區是這一頁真正有價值的東西）

**問題**：三種做法跟「不判斷」大多數日子方向一樣。方向一樣的日子，兩邊的結果**完全相同**、差值是 0。
所以「5 分 K 比不判斷多賺 234 點」的**有效樣本數不是 20，是「結果不一樣的那幾天」**。
把 20 當成樣本數會嚴重高估這個比較的可信度。

三張小卡（⛔ v3：標題兩邊都寫名字，不寫 `A − D`）：

```
5 分 K  vs  不判斷
不一樣的只有 10 天  / 20 天
5 分 K 贏 6 · 不判斷 贏 4 · 差 +234.6 點
● ● ● ● ● ● ● ● ● ●        ← 每天一個圓點（紅＝那天多賺、綠＝那天少賺）
多的那邊 6 天 · 要 9 天才算數
```

- ⚠️ **圓點的紅綠＝「多賺／少賺」，跟全站「紅賺綠賠」同一個意思**（§4.4）。
  v2 的 `title` 寫成「紅＝A 贏、綠＝D 贏」，那是**另外一套要記的密碼**，已改掉。
- ⚠️ 最後一行 v2 寫「贏 6 次」，但那個數字是 `max(w,l)`——**可能是「不判斷」贏的次數**，
  寫「贏」會指錯人。v3 改成「**多的那邊 6 天**」。

⚠️ **v2 砍字**：v1 最後那句是「這 10 天等於擲 10 次銅板。要算數至少得贏 9 次，現在是 6 次。」
——同一件事，v2 只留兩個數字，那句完整的話進 `title`。⛔ 卡片下方**不再有**解釋段落
（v1 有一段講「有效樣本數不是總筆數」的話，已移到卡片標題的 `title`）。

- 「結果不一樣的天數」`m` 的定義：`dir[k] !== dir.D`，**或** `dir[k]===0`（C 沒做的日子，
  那天 D 有做、C 沒做 ⇒ 結果當然不一樣）。
  ⚠️ 標題用「**結果不一樣**」不用「方向不同」 —— C 沒做的日子不叫「方向不同」。
- 判準（二項式 95%）：`need = ceil((m + 1.96√m) / 2)`。
  - m=7 ⇒ need=7（**七天全贏才算數**）；m=10 ⇒ need=9；m=20 ⇒ need=15。
  - ⛔ **這個算式是 lab-ux 推的，dev 上線前要跟 PM 確認**（同 §7.1 的處置）。
- 圓點列是這一區的靈魂：**十個點就是十個點**，他一眼看得出可以拿來比的東西有多少。
- ⛔ 這一區**不准**出現「某某領先」「某某較優」這類措辭。只寫次數與「還不算數／值得再看下去」。

### 9.3 ⛔ 四個進場點怎麼標才不打架 ——「泳道」

**問題**：四種做法在**同一時刻、同一個價**進場 ⇒ 四個進場標記完全重疊；
出場價又只有三種可能（+100 / −100 / 收盤價）⇒ 出場標記的 y 也重疊。

**解法：價格區只放「一個」，四條的身分全部下放到泳道。**

價格區（上 ~70%）只畫：

1. 1 分 K 棒（紅漲綠跌）
2. **一個** 09:03:30 的進場標記（◆ ＋ 金色垂直虛線貫穿全圖）＋ 標籤 `09:03:30 模擬進場 12158.4`
   —— 因為事實上就是同一個時刻同一個價，畫四個是**假的**。
3. **兩條** ±100 線（`進場價 +100` / `進場價 −100`，`--line` 虛線）
   ⛔ **不准標「停利／停損」** —— 同一條線對做多是停利、對做空是停損，標了一定有一邊是錯的。
4. 他自己那一單（▲/▼ ＋ 淡帶 ＋「真」，沿用即時分頁的標記語言）


#### ⛔⛔ 泳道左邊放的是名字，不是代號（v3，這一條被退件過）

Benson 的原話：「我要從哪裡知道現在我看的是哪個做法？」——v2 泳道左邊只有一個字母。
**放不下不是縮寫的理由，是重新排版的理由。**

- **名字欄寬度用量的，不是猜的**：畫之前先 `ctx.font='600 11px <font-sans>'`，
  對四個 `nm(k)` 各跑一次 `measureText().width`，取最大值 `NW`，
  **名字欄寬 `L = ceil(NW) + 18`**（實測桌面 1240px 時 `L = 103px`，佔繪圖區 10%）。
  ⛔ 不准寫死一個 px 值 —— 門檻改成 3 位數（`開盤起・要 200 點`）名字就變寬。
- **名字欄與 K 線圖共用同一條左界**：`X(mi) = L + 4 + mi/NB*(PW-L-8)`，
  ⛔ K 棒與泳道**必須用同一個 `X()`**，否則泳道的色帶跟上面的 K 棒對不到同一個時刻。
  價格刻度仍在右邊；**±100 的兩張籤搬進左邊名字欄**（右對齊 `L-8`），
  順便解決 v2「進場價 +100 壓在 K 棒上」的問題。
- 名字：`--dim`、`600 11px` sans、**右對齊在 `L-8`**、垂直對齊色帶中線。
  ⛔ 不准比 11px 更小（v2 的代號是 10px mono，那是代號才擠得下）。
- **窄視窗的退路（⛔ 仍然不縮寫）**：`L > 繪圖區寬 × 0.25` 時自動切成**堆疊排法**——
  名字自己一列（左對齊、貼齊繪圖區左界，`L=0`）、色帶在下一列，列高 22 → **30px**。
  實測 430px 寬會切到這個排法，四個名字全部完整。
  ⚠️ 切成堆疊後泳道區多吃 32px，**圖要跟著變高**（demo 用
  `@media(max-width:720px){.cwrap.day{aspect-ratio:520/620}}`），
  否則 K 線被壓成 34px 一條（demo 實測過，很醜）。⛔ 不可以改成壓縮泳道。
- 每條泳道：從 09:03:30 拉到自己的出場時刻，色帶顏色 = **紅賺綠賠**（那是損益，可以用紅綠）。
- **「開盤起・要 N 點」不做的日子畫成空的虛線 ＋「這天不做（訊號 +2.3 點，不夠）」**，
  ⛔ **不可以整條消失**（消失＝壞掉，跟「休市日要選不到」是同一類處置）。
  ⚠️ 那條虛線要**從文字後面才開始畫**（`x = 文字結束 + 8`）——v2 整條穿過文字，字糊掉。
  ⚠️ 也不要再重複寫「沒超過 30」——名字裡已經寫著「要 30 點」了。
- **「不判斷」跟別人同向的日子，泳道就是長得一樣** —— 那是事實，不是 bug，不要去合併它們。
  合併掉的話「今天判斷有沒有加分」正好看不見。
- ⚠️ **泳道標籤的顏色**：放得下就用色帶顏色放在色帶右邊；放不下疊在色帶上時**改用 `--text`**。
  同色字疊在 30% 透明的同色帶上讀不清楚（demo 第一版踩到，截圖才看見）。
- 出場落在畫面外（切到「只看 08:45~09:30」時）⇒ 色帶拉到右緣 ＋ `▶` ＋ 標籤寫「畫面外 13:40 停利」。
  ⛔ 不可以把標記黏在邊緣假裝畫得出來。

### 9.4 價格軸

- `niceStep()` 貼齊（**必抄**）。
- ⛔ **±100 與交易標記都不准撐大價格軸**。畫不到就掛邊緣籤
  （`↓ 進場價 −100 在畫面下方 42 點`）。
- ⚠️ 真實單的 `exit` 可能是 `null` ⇒ `Math.min(lo, entry, exit)` 會把它當 **0**，
  價格軸整個掉到 0（2026-09-02 踩過）。**餵進算式前一律先 `!= null` 過濾。**
- 分鐘軸印 `HH:MM`。（⛔ 印到秒是【細節】的事，這一頁印秒反而會讓人以為在看秒級圖。）

### 9.5 翻頁

**沿用【細節】那一套**（`◀ 日期 ▶ 今天`、鍵盤 ← → Home、日期鈕點開清單 popover），
逐項照抄它的四道守衛（TICK-TAB-SPEC §6.3）：流水號、`AT.date` vs `AT.data.date` 兩個欄位、
沒錄到的日子選不到、**日期鈕寬度不准隨狀態變**。

⚠️ **翻頁只影響「這一天」那張卡，不影響上面的成績與累計圖。**
這件事要在畫面上看得出來 —— 「這一天」卡的標題自己帶日期，成績卡的標題帶的是「N 個交易日」。
⛔ 不要把兩者綁在一起（那會讓「翻到某一天」變成「只看那一天的統計」，
而這一頁的重點是跨日累積）。

清單 popover 每列：`09-08 一 · A空 B多 C— D多 · 當天合計 +100`。
⚠️ 母體是「有記錄的日子」，上線第一週只有 0~3 天 ⇒ **用清單不用月曆**
（95% 格子是灰的月曆傳達的是「壞了」而不是「沒有資料」）。

## 10. 進階：門檻掃描（摺疊，預設收起）

這是 §3.1「記數值不只記方向」的兌現：滑桿調 C 的門檻（0~200 點），就地重算成績。

⛔⛔ **但這個功能離「找訊號」只有一步之遙**，所以硬性限制：

- ⛔ **不顯示「最佳門檻」**、⛔ **不畫「門檻 vs 報酬」的曲線圖**。
  那種圖會讓人一眼挑峰值，而峰值幾乎一定是雜訊。
  只給一張**固定幾檔**（0 / 20 / 30 / 50 / 80 ＋ 目前值）的表。
- 每一列**照樣套天花板**，而且要讓他看見：**門檻越高 ⇒ 筆數越少 ⇒ 那條線越高**。
  表格底下常駐**一行**：`門檻越高 ⇒ 筆數越少 ⇒ 那條線越高`（v1 那句「門檻拉到 80 點只剩幾筆
  的時候，那一列的數字幾乎沒有意義」進 `title`）。
- 摺疊**裡面**（不是外面）留**一行**：`不是在找最佳門檻（刻意不標最好的那一列）`；
  「同一批資料被問越多次，挑到最好看的那個門檻通常只是挑到雜訊」那段進 `title`。
  ⛔ 規則不變：**不顯示「最佳門檻」、不畫門檻對報酬的曲線**。
- ⛔ 調整滑桿**不會改變真正在跑的 C**（`C_THRESH` 是常數，只有 PM 能改）。
  這件事要寫出來，不然他會以為調了就生效。
- **預設收起。** 攤開會讓整頁的重心從「對照實驗」滑向「調參找訊號」。
  ⚠️ 這一顆要不要做，請 PM 拍板（§16-4）。

## 12. 狀態（空／載入／錯誤）

**上線第一天是 0 筆，第一週是 1~5 筆。空狀態是主流程，不是邊角。**

| 狀態 | 判定 | 畫面 |
|---|---|---|
| 一筆都沒有 | `days` 空 | 「還沒有任何一天的模擬紀錄。明天早上 09:03:30 會自動記下第一筆。」＋「不用做任何事，也不會有單送出去。」＋ 天花板橫幅寫「0 筆 ⇒ 什麼都測不出來」 |
| 1~9 筆 | `n < 10` | 成績表照畫（含天花板），**累計圖不畫線**、改空狀態；勝率欄一律「不到 30 筆，不算 %」 |
| 今天還沒到 09:03:30 | 後端時鐘 | §4.2 等待態 |
| 今天記錄失敗 | 那天沒有列 | 「今天沒有記錄」＋原因（斷線／休市／面板 09:03:30 時沒開） |
| 結算未完成 | 有 `sig` 沒有 `runs` | 那幾格寫「持倉中」或「結算中」，⛔ 不可以顯示 0 或空白 |
| 載入中 | `AT.date !== AT.data.date` | 圖區骨架（高度跟真圖分毫不差：`aspect-ratio` 同值 ＋ 假 K 棒**絕對定位**）；筆數整組藏起來 |
| 檔案讀不出來 | 端點 500 | 「這個月的紀錄讀不出來（第 N 列壞掉）」＋翻頁列照常在 ＋「重試」 |

⛔ **任何狀態下翻頁列都不准消失**（面板 2026-08-25 修過同一個病）。
⛔ **一列壞資料只准弄掉那一列並計入 `bad`，不准弄掉一整個月**
（【細節】分頁 2026-09-07 踩過：一列壞 `price` 讓整天回 500，1,091 列好資料一列都看不到）。
所有數值欄位過 `_num()`，**bool 要另外擋**（`isinstance(True, int)` 是 True）。

## 15. 驗收條款（dev 自測 ＋ lab-qa 照著量）

> 每一條都要有**量法**與**負控組**。沒有負控組的綠燈在這個專案不算數。
> 探針：`tools/probe/autotest-tab.mjs`（真瀏覽器，沿用 `cdp.mjs`）
> ＋ `tools/probe/autotest-backend.py`（離線）。
> 治具用合成資料，⛔ **一個真實成交價、真實進出場時間、真實點數都不准進探針或治具**
> （價格一律 12000 附近，46xxx/47xxx 會撞到他的真實紀錄）。

**1. ⛔ 這一頁碰不到下單路徑**
AST 掃 `live_panel.py` 裡 `#tab-auto` 相關的函式與後端 `auto_*`：
不得出現 `broker`、`place_order`、`/api/enter`、`/api/real/`、`REAL_ORDERS_ON`。
前端掃 `#tab-auto` 的 DOM：`[data-act]`、`[data-rdir]` 必須是 0 顆。
**負控組**：同一把尺對 `hold-to-fire` 那段程式必須抓得到 `broker` ⇒ 證明尺是活的。

**1b. ⭐ 文字預算（v2 新增；退件就是退在這條）**
量 `#tab-auto` 第一屏（`getBoundingClientRect().top < 視窗高`）內每個**葉節點**的
`round(height / line-height)`：⛔ **不得有任何 ≥ 3 行的散文塊**
（表格/圖例/按鈕不算，判準是「該節點沒有子元素且字數 > 30」）。
另外斷言 `.at-about` 與 `.at-adv` 的 `open === false`（**預設關著**），
且 `.at-about` 的條目數 **=== 10**（§4.5 那十條）——
⚠️ 收摺過的東西最容易被下一個人整段刪掉，這條斷言擋的就是這件事。
**負控組**：把 `.at-about` 的內容塞回第一屏 ⇒ **必須紅**；刪掉其中一條 ⇒ **必須紅**。

**1c. 「模擬」鎖印恰好 1 顆**
`document.querySelectorAll('#tab-auto .simlock').length === 1`，且 computed `display !== 'none'`。
**負控組**：把它 `display:none` ⇒ 必須紅。（⛔ 兩顆也算紅：v1 的三處是退件原因之一。）

**1d. 進度尺會動**
灌 20 天 ⇒ `.at-track` 文字含 `20 / 505`；灌 120 天 ⇒ 含 `120 / 505`
且填色寬度比值介於 `(20/505, 120/505)` 的 ±10% 內。
掃 `.at-track` 的 `textContent` **不得**出現 `檢定力|功效|MDE|顯著|信賴區間|p 值`。
**負控組**：把 505 寫死成 n ⇒ 進度永遠 100% ⇒ 必須紅。

**1e. ⭐⭐ 畫面上一個代號都沒有（v3 新增；這一輪的退件就是退在這條）**
① **DOM**：`#tab-auto` 的 `innerText` 用 `/(^|[^A-Za-z0-9])[ABCD]([^A-Za-z0-9]|$)/g` 掃，
**命中數必須 === 0**（demo 實測 0）。
② **canvas**：攔 `CanvasRenderingContext2D.prototype.fillText`，**把這一頁畫過的每一個字串收集起來**，
同一把尺再掃一次 ⇒ 也必須 0。（⛔ 只掃 DOM 會整片漏掉泳道與累計圖的標籤，
那正是 Benson 抱怨最兇的地方。）
③ **四處同名同序**：從「今天卡抬頭」「成績表第一欄」「泳道標籤（canvas 攔截）」
「累計圖線尾標籤（canvas 攔截）」各抽一份名字陣列，**四份必須完全相等**
（含順序，且等於 `AT_ORDER.map(atName)`）。
④ **門檻連動**：把常數 `C_THRESH` 改成 `80`，上面四份必須同時變成 `開盤起・要 80 點`。
⑤ **⛔ 反向：拉進階區的滑桿到 80，上面四份必須「完全不變」**（仍是 `開盤起・要 30 點`）——
滑桿只是試算，不是改設定（§2.0、§10）。
**負控組**：把泳道標籤改回畫 `k` ⇒ ①仍綠但②③必須紅（⇒ 證明 canvas 那把尺是活的）；
把成績表某一列的名字硬寫成 `'開盤起'`（不呼叫 `atName`）⇒ ④必須紅。

**1f. 名字沒有被截斷／縮寫（v3 新增）**
泳道名字欄寬 `L` 必須 `>= ceil(max(measureText(四個名字))) + 18`；
非堆疊排法時，斷言 `L > 0` 且每個名字的 `measureText().width <= L - 18`。
**⛔ 不准用字級推算**（手冊：版面尺寸一律實際量）——用該 canvas 的 `ctx.measureText` 實測。
視窗寬度掃 `[1440, 1240, 1024, 768, 600, 430, 360]` 七個點，
每一點都要滿足「名字完整可畫」（堆疊或非堆疊皆可，但**不得縮寫**）。
**負控組**：把 `L` 寫死成 `24`（v2 的代號寬度）⇒ 必須紅。

**2. 少樣本不給百分比**
灌 3 天的合成資料。斷言 `#tab-auto` 的成績表 `textContent` **匹配 `/\d+%/ === null`**。
**負控組**：把 `RATE_MIN_N` 改成 0，這一條**必須紅**。
（demo 已用「危險對照」開關驗過這個負控組真的會紅。）

**3. 樣本 < 10 不畫累計線**
斷言 canvas 上沒有任何折線（攔 `ctx.stroke` 計數 = 0，或空狀態文字存在）。
**負控組**：把 `CUM_MIN_N` 改成 0 ⇒ 必須有線。

**4. 紅線：無預測字眼**
掃 `#tab-auto` 的 `textContent` ＋ 所有 `title` / `aria-label`，
**⛔ 還要攔 canvas 的 `fillText`**（這一頁畫在 canvas 上的字有：進場標籤、泳道標籤、
「這天不做」、邊緣籤 —— 只掃 DOM 會漏掉，【細節】分頁 2026-09-07 為此退件過 M2）。

```
預測 預估 預期 勝率預估 期望值 建議 訊號強度 看漲 看跌 準確率
目標價 支撐 壓力 買點 賣點 該進場 可以進 追多 追空 突破訊號 共識 多數決 最佳
```

⚠️ **v2 之後這條更重要**：被砍掉的解釋都搬進 `title` 了，所以**掃描一定要含 `title`**，
而 `title` 裡幾乎都是否定句（「那就是預測了」「不是建議」）——
下面那條「否定上下文」判準是這條規則能不能用的關鍵，⛔ 不准為了圖方便把 `title` 排除掉。

⚠️ 「建議」「預測」等字**允許出現在否定句裡**（「不是建議」「這一頁不預告」），
所以判準是：命中時取前後 24 字的上下文，必須含
`不是|不做|不准|不會|沒有|⛔|不顯示|不預告` 其中之一。
**負控組**：往 DOM 塞一個「今天建議做多」的節點 ⇒ **必須紅**（demo 實測會紅）。

**5. 紅線：方向不用紅綠**
量 `.at-today .dir` 每一顆的 computed `color`，
**不得等於** `rgb(238, 90, 84)` 或 `rgb(52, 179, 126)`。
另外逐一量所有用到 `--up`/`--down` 的元素，確認它代表的是漲跌或賺賠；
**筆數、門檻、訊號值、天數用到紅綠就退件**。
**負控組**：把一顆 `.dir` 的 color 改成 `var(--up)` ⇒ **必須紅**。

**6. 鎖印真的畫在畫面上**（v2：見上面 1c，`.simlock` **恰好 1 顆**且 `offsetParent !== null`）
**負控組**：設成 `display:none` ⇒ 必須紅；複製成 2 顆 ⇒ 也必須紅。
⚠️ ⛔ 不可以只斷言「原始碼裡有那個字串」—— 他看的是畫面。

**7. 天花板常駐，而且是算出來的**
`#atceil` 可見；文字符合 `/每筆差 [\d.]+ 點以上/`（v2 文案）；
**n=20 的值必須大於 n=120 的值**（證明它隨筆數變，不是寫死的字串）。
**負控組**：把 `atCeiling()` 改成回傳常數 ⇒ 兩個值相等 ⇒ **必須紅**。

**8. 「不預告」**
把後端時鐘設在 09:01。斷言「今天」卡**不含任何方向字樣**（`做多`/`做空`），
且含「還沒到」。
**負控組**：拿掉那道時間守衛 ⇒ 出現方向 ⇒ **必須紅**。

**9. 回測與實跑不相加**
治具給 10 筆 `src:"live"` ＋ 200 筆 `src:"backfill"`。
斷言 `/api/auto/stats?src=live` 回的 `n === 10`，且畫面上的天花板是 n=10 的值。
**負控組**：把 `src` 過濾拿掉 ⇒ `n === 210` ⇒ **必須紅**。

**10. 每一列都要有去處**
`n + skipped + bad + missing === 檔案裡的總天數`。
這是「有沒有東西被安靜吃掉」唯一的機器判準（沿用【細節】②b-2 的做法）。

**11. 泳道不打架**
造一天：四條同一時刻進場、其中兩條同向、「開盤起・要 N 點」不做。斷言：
- canvas 上「09:03:30 模擬進場」這個字串**只出現一次**（攔 `fillText`）
- 四條泳道的 y 區間兩兩不重疊
- 「開盤起・要 N 點」那條的文字含「這天不做」且含訊號值，
  且**那條虛線不得與該段文字的 x 區間重疊**（v3：虛線要從字後面才開始畫）
- 只切到 08:45~09:30 時，出場在畫面外的那幾條標籤含「畫面外」
**負控組**：把泳道的 y 偏移拿掉（四條疊在一起）⇒ 重疊檢查**必須紅**。

**12. 版面**
- 量 `.at-*` 底下每一個有 `max-height` 的 flex 直欄，子元素 `flex-shrink` **必須是 0**。
- 骨架與真圖高度差 ≤ 0.5px（CLS = 0）。
- 視窗寬 1024 / 1280 / 1440 各量一次：不可以橫向溢出、canvas 不可以變形。
- 成績表在 390px 寬時**橫向捲**，⛔ 欄位不可以被壓扁（量每一欄的 `scrollWidth` vs 欄寬）。
**負控組**：加一個 `flex-shrink:1` 的子元素 ⇒ 必須紅（demo 實測會紅）。

**13. canvas 尺寸不亂動**
包住 `canvas.width` 的 setter 計數。連續 200 次重畫（不改視窗尺寸）⇒ 呼叫次數**必須是 0**。
**負控組**：真的改視窗尺寸 ⇒ 計數 **必須 > 0**（證明計數器不是恆 0）。

**14. 換日不會錯置**
延遲第一個 `/api/auto/day` 800ms、連按 ◀ 5 次。斷言最後畫面上的日期 = 最後一次請求的日期；
過程中 `AT.date !== AT.data.date` 時畫面上不准出現任何數字。
**負控組**：拿掉 `if(my!==AT.seq) return` ⇒ 必須紅。

**15. 不影響停損**
切到【程式下單】停留 60 秒，量主迴圈的停損檢查週期（要用**獨立治具**，
⚠️ `fe_harness.py` 沒有 4Hz 主迴圈，結構上量不到 —— 別在那裡假裝量得到）。
對照組用 `/api/bars` 換日（既有功能，實測 1732 ms）。
這一頁的資料量小，**應該遠低於對照組**；高於對照組就要查。

**16. 洩漏掃描**
`py tools/probe/leak-scan.py` 必須零命中（commit 前一定要跑）。
⚠️ 這一頁新增的 `autotest/` 資料夾要**先加進 `.gitignore` 再產生第一筆資料**。

## 17. ⚠️ lab-ux 認為這個需求本身有問題的地方（直說）

1. **09:03:30 是在雜訊裡挑的**（§2.3）。09:03 (+2.00) 與 09:04 (−2.10) 差 4.1 點，
   而那批資料的天花板是 12.1 點。**這個時刻沒有被證明比較好。**
   這一頁如果做得漂亮，會反過來讓「09:03:30」看起來像一個經過驗證的參數 ——
   所以 §4.5 那條紅線不是禮貌性的免責，是**這一頁能不能存在的條件**。
   ⚠️ v2 把它收進摺疊之後，**它更容易被下一個人整條刪掉** —— 收摺不等於可以砍，
   §15-1b 的驗收要連 `.at-about` 的**條目數**一起斷言。

2. **二十天什麼都證不出來，而且會證不出來很久。**
   20 筆的門檻是每筆 **60.8 點**，而 ±100 規則的單筆上限就是 100 點。
   要壓到 12.1 點需要約 505 筆＝**約兩年**。
   ⇒ 這一頁在可預見的未來，**唯一誠實的輸出就是「還看不出來」**。
   如果他期待的是「累積二十天就知道哪個好」，那個期待現在就要調整，不要等二十天後才發現。

3. **四條線高度相關，不是四個獨立實驗。** 大多數日子三種做法同向 ⇒
   有效樣本數遠小於天數（§8）。這件事如果不在畫面上講清楚，
   「5 分 K 比不判斷多賺 234 點」會被讀成一個 20 筆的結論，實際上它是 10 次擲銅板贏 6 次。

6. **（v3 新增）「5 分 K」這個名字我有意見，但照做了。**
   四個名字裡有三個是「**從哪裡起算**」（開盤起／開盤起・要 30 點／不判斷），
   只有 `A` 是「**用什麼圖**」（5 分 K）——**兩種語彙混在一起，A 跟 B 差在哪就看不出來了**
   （實際上只差起算點：09:00 vs 08:45）。而且這一頁的圖畫的是 **1 分 K**，
   泳道左邊出現「5 分 K」有撞詞的風險。
   ⇒ **我的建議是 `A` 改叫「09:00 起」**（跟「開盤起」同一句型，一眼看出只差起算點）。
   ⇒ **但沒有自作主張改**：名字是 Benson 定的，而「5 分 K」是他自己對那條規則的說法，
   對他而言查表成本本來就是零；成績表小字已經補上「09:00 起算」把差異講明。
   **請 PM 拿這一條問他一句就好**，他說不改就維持現狀（改動成本 = 改一個字串常數）。

4. **「他自己那一欄」的口徑對不上，而且差很多**（§11）。
   一天 0~3 筆 vs 恰好 1 筆、時刻不固定、有手動平倉。
   並排是他要求的，但**必須配上「同口徑」那一列**，否則這一欄會給出錯誤的自我評價 ——
   而 CLAUDE.md 說這是「唯一還沒被否定的假設」，把它評價錯的代價比其他四條都高。

5. **這一頁會不會變成盯盤的理由？** 這是我最擔心的一件事，而且規格擋不住。
   每天早上多一個「今天程式判斷做多，來看看它對不對」的畫面，
   是一個**很輕、每天都會發生、而且會慢慢改變他行為**的東西。
   ⇒ 建議 PM 在上線一個月後主動問一次：
   「這一頁有沒有讓你在 09:03:30 前後多看了幾眼？」
   如果有，那它的成本就不只是幾百 KB 的磁碟。
